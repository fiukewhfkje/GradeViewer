# Copy to Muse with the private experiment ZIP

The ZIP contains two separately captured owner sessions and their wrapping keys. It contains no OSU password or Mac Cloudflare OAuth credential. Keep it in private VM storage outside a Git checkout. This prompt itself contains no credentials.

```text
Run this finite Carmen session experiment using the attached private ZIP. Use ordinary shell/Node cron, with no LLM invocation on ticks. Do not deploy a Worker, publish anything, upgrade a Cloudflare plan or modify production GradeViewer.

1. Unpack into an owner-only persistent directory, such as ~/.local/share/gradeviewer-carmen. Run the enclosed install.sh from the extracted carmen-muse-experiment directory. It installs pinned Playwright Core/Wrangler, records the absolute Node path and installs no scheduler. Node 24+ is required. Cloud recovery is remote, so no local Chromium binary is needed for the default experiment.

2. The VM must have its own authorized Wrangler login to the owner's Cloudflare account for ACTUAL Cloudflare browser-time measurements. No Mac Cloudflare token is included. If already authenticated, retain it. Otherwise use the pinned CLI's `login --device` flow and have the owner authorize Cloudflare normally; do not request an OSU API token. Do not log the OAuth token, identity details or full private handoff URLs. The private cloudflare-account.json binds the expected account, and init checks it. Do not use another/shared account, a paid upgrade, or --local-browser to claim the Cloudflare budget passes.

3. Run `./run-experiment.sh init` ONCE. It performs one initial HTTP-only, no-renew profile-plus-courses verification for each transferred profile, then creates the coordinator with Cloudflare recovery selected. A schema-valid empty [] is expected because the owner has no courses. This establishes the baseline on THIS VM before the quiet waits. If either baseline fails, stop setup and report a sanitized migration/technical/auth outcome; do not invent an expiry duration or start cron. Repeating init after successful initialization is refused before requesting Carmen again.

4. Run `./run-experiment.sh tick --observe-recovery`, then `./run-experiment.sh status`. On success, install a system-cron entry every minute calling the ABSOLUTE path to run-experiment.sh with `tick --observe-recovery`, appending only its sanitized stdout/stderr to a private mode-600 cron.log. Do not schedule a model/Muse agent every minute.

5. A tick is normally local-only until due. The active profile checks the real Canvas profile and enrolled-courses-with-total-scores endpoint every five minutes. The idle profile waits 2h, then 4h, 8h, 16h, 24h, then 48h from each preceding successful check. Do not make other requests from either profile, including the Mac copies, after this handoff. Each success may reset that session's idle timer. The sequence is not a week without requests; no extra weekly quiet probe is authorized by this bundle.

6. Measurement requests always use --no-renew and record success/auth rejection/inconclusive before any recovery. With --observe-recovery, the runner separately invokes ONE bounded headless Cloudflare renewal for a confirmed rejection, after preserving the measurement. It logs OSU silent continuation/credential prompts, Duo challenge evidence, AUP/other human prompts, technical errors and verified success separately. Never infer Duo from a timeout or merely loading a Duo URL. Never automate passwords, Duo approval or policy acceptance. A human requirement pauses that probe. Repeated expiry/recovery episodes, not idle probes alone, measure how often human action is needed.

7. Benchmark browser USAGE and latency. The routine-recovery target is at most 120 seconds per 24 hours, comfortably below the Free-plan 600-second daily allowance. The runner records each browser's wall interval through close acknowledgement, separates Cloudflare from VM timings, spaces launches, checks account-wide Cloudflare analytics before recovery, and defers rather than repeatedly launching when budget is low/unknown. Initial manual sign-in and other workloads also count against the account-wide allowance; local wall time is not exact billed usage. Run `./run-experiment.sh budget` and the enclosed Cloudflare status command for account telemetry. Unknown/missing costs, cleanup failures, deferrals and local-only samples cannot be treated as a pass. Report the observed worst day/rolling 24h, maximum per-attempt time, number of recoveries, human steps and gaps in evidence. A budget pass alone does not prove low-maintenance login behavior.

8. Keep notifications quiet on ordinary success. Notify the owner once on a meaningful pause, human requirement, cleanup failure, budget hold or completion, giving only probe role, fixed reason, UTC time and safe latency/retry information. Do not keep a browser open awaiting a human. Do not retry failed renewal every minute. A first Cloudflare human prompt can reflect host/browser migration from the initial Mac capture, so do not call it a measured steady-state MFA frequency or exact SSO timeout.

9. Stop network/browser work at the coordinator's explicit endsAtUTC (no later than the profile's seven-day-from-capture authorization), remove this experiment's cron entry at completion, and retain private files for the owner's review. Do not extend state authorization, clear sessions or delete unrelated data. Report the actual baseline/start/end timestamps; active failures bound expiry between last success and rejection, while network/403/429/server/malformed responses are inconclusive. Do not claim an exact timeout from a late check.

10. Share only sanitized observations/status/budget reports with the owner. No cookies, keys, passwords, account IDs, raw responses/HTML, student identity, course names or grade values in chat, logs or Git. The app itself remains independent of Muse; this is diagnostic work to decide whether a Canvas settings option can be seamless, low-maintenance and safely within the free browser budget.
```
